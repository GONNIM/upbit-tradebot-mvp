# 투자자 답변 분석 — 수정사항(11/21) 질문 ㉠~㉣ 답과 추가 요청 2가지

- 작성: 2026-11-23 · 원문: `investor-answer-20261123.md` · 질문: `investor-questions-20261121.pdf`(html 같은 폴더)
- 관련 일: HANDOFF 1121-03(투자자 수정 요청 화면 고치기), 계획 2판(지난 세션 임시 폴더 `fullback-plan-draft.md`)
- 범위: 읽기와 분석만 했다. 코드·서버·설정은 바꾸지 않았다.

## 1. 한눈에

| 질문 | 투자자 답 | 권장(①)과 같은가 | 계획에서 바뀌는 것 |
|---|---|---|---|
| ㉠ 1% 줄의 뜻 | ① + 간격을 0.5%로 | 방식은 같고 간격만 다름 | 간격 1% → 0.5%, 줄 수 상한 다시 정함 |
| ㉡ 홈에도 설정 한 줄 | ① | 같음 | 없음(운용 화면 + 홈 「보유」 아래) |
| ㉢ 감사 로그 어느 줄 | ① | 같음 | 없음(「설정 적용」 줄에만) |
| ㉣ TS 뜻 | ① + 추적 손절 켬이면 켬/방식/폭 표시 | 같음, 표시가 자세해짐 | 추적 손절 칸 표시 모양 |
| 추가 1 | 백테스터를 마지막 저장값으로 열기 | 새 요청 | 새 범위(백테스터 시작값) |
| 추가 2 | 차트 탭에 백테스터 차트 모양 적용 가능한지 | 새 질문 | 새 범위(차트 탭) — 답(가능 여부)이 먼저 필요 |

## 2. 질문별 분석

### ㉠ 「1% 줄」 → ① 방식, 간격 0.5%
- 뜻: 매수 뒤 평단 대비 +0.5%, +1.0%, +1.5% … / −0.5%, −1.0% … 에 **처음** 닿을 때마다 감사 로그에 한 줄. 봉 종가 기준, 평단이 바뀌면 새 평단으로 다시 센다(질문 PDF의 ① 설명 그대로).
- 바뀌는 점: 같은 값 움직임에 줄이 두 배다. 위아래로 오락가락해도 같은 단계는 한 번만 나오므로, 줄 수는 「오른 폭 + 내린 폭 ÷ 0.5%」로 정해진다.
- 상한 문제: 계획 2판은 보유 1건당 최대 20줄이다. 0.5% 간격이면 위아래 합쳐 10% 움직임에서 20줄이 다 찬다. 손절 5% · 익절 1.5% 설정이면 정상 범위(−5%~+1.5%, 약 13줄)는 들어간다. 추가 매수로 평단이 바뀌면 다시 세므로 줄이 더 늘 수 있다.
- 정할 것: 상한을 20줄로 둘지 40줄로 올릴지(1%일 때와 같은 폭 20%를 덮으려면 40줄).
- 질문 PDF 에 「거래 한 번에 최대 20줄」이라고 이미 알렸다. 40줄로 바꾸든 20줄로 두든(덮는 폭이 20% → 10%로 줆) 배포 전 체감 변경 안내에 적어야 한다.
- 계획 3판에 정할 규칙(Fable 권고): 상한에 닿으면 어느 줄을 남길지(옛 줄 / 최근 줄), 평단이 바뀌어 다시 셀 때 상한을 합쳐 셀지, 한 봉이 0.5% 단계를 2개 이상 넘으면 줄을 몇 개 낼지.
- 그대로인 제약: 봉 종가로만 보므로 봉 안에서 잠깐 닿은 것은 안 나온다. 기록 창은 1,200행 고정이라 3분봉이면 약 60시간, 1분봉이면 약 20시간보다 오래된 줄은 사라진다(v2/api_read.py:123~139). 서버의 지금 봉 단위는 이번에 확인하지 않았다.

### ㉡ → ① 두 곳 모두
- 운용 화면 「매매 전략」 아래와 홈 「보유」 아래에 같은 설정 한 줄. 계획 2판 그대로다.
- 질문 PDF에 이미 알린 점: 이 줄은 「지금 설정」이라, 보유 중 지금 쓰이는 값(추적 손절은 살 때 값 등)과 다를 수 있다.

### ㉢ → ① 「설정 적용」 줄에만
- 계획 2판 그대로다(매수·매도 줄에는 붙이지 않음).

### ㉣ → ① 익절과 추적 손절 둘 다 + 추적 손절 켬이면 「켬/방식/폭」
- 투자자 글: 「TS(추적손절) - 추적손절 켬 일경우 켬/방식/손절폭(00%) 표시」.
- 표시 예(꺼짐): `익절 1.50 / 추적 손절 끔 / 손절 5.00 / 분할 1 / 기울기 0.60 / 둔화 0.20 / 투자비율 100%`
- 표시 예(켬): `익절 1.50 / 추적 손절 켬 · 비율 · 50% / 손절 5.00 / …`
- 방식 낱말은 백테스터 칸과 같은 「비율」·「고정폭」을 쓴다(v2/static/backtester.html:153, save.js:96).
- 계획 2판은 「TS 비율 50」처럼 줄여 쓰려 했다. 투자자 글대로 「켬」 낱말을 넣고 폭에 % 를 붙인다. 「손절폭」은 화면에서 「폭」으로 쓸지 「손절폭」으로 쓸지 구현 때 투자자 낱말(손절폭)을 따른다.
- 이 표시는 운용 · 홈 한 줄과 감사 로그 「설정 적용」 줄 모두 같은 모양으로 쓴다(같은 함수 하나로).

## 3. 추가 요청 분석

### 추가 1. 백테스터를 마지막 저장값으로 열기
- 투자자 글: 「백테스트 기본설정을 마지막으로 저장 또는 운용중인것으로 불러오기 … 저장한거 없을경우 현재 기본설정으로」. 이유는 1~2칸만 바꾸고 싶은데 매번 모든 칸을 다시 맞추기 불편하다는 것.
- 지금 화면: 백테스터를 열면 칸마다 화면에 박힌 기본값으로 시작한다. 종목과 봉 단위만 엔진 상태를 읽어 바꾼다(v2/static/bt_ui.js:401~414).
- 가능 여부: 가능하다. 저장본 파일을 읽는 길은 이미 있다(GET /v2/api/params/current — 저장 창이 쓰는 것, v2/api_write.py:182~202). 저장 이력을 읽는 길은 새로 만들어야 한다(아래).
- 「저장」과 「운용 중」은 다른 파일이다.
  - 저장본: `<사용자>_latest_params_PULLBACK.json` — 「설정 저장」 단추가 쓰는 파일(v2/db.py:240).
  - 운용본(적용본): `<사용자>_applied_params_PULLBACK.json` — 엔진이 지금 쓰는 값(v2/db.py:246).
  - 「저장만 하기」를 하고 적용하지 않으면 두 파일이 다르다. 투자자 글은 둘 중 어느 쪽을 먼저 쓸지 정하지 않았다.
- 「저장」에는 두 가지 기록이 있다(Fable 지적으로 고침, 코드로 다시 확인).
  - 저장본 파일: 엔진 모양 24키다. 「기간(days)」과 「데이터 출처(업비트/바이낸스)」가 없다(v2/params_schema.py:216~244). 종목은 백테스터에서 시험한 종목이 아니라 **저장할 때의 엔진 종목**이다(v2/api_write.py:84·103·145~156). 이 파일은 배포 때부터 있고(없으면 저장이 500 으로 거절됨, api_write.py:93~99), 거래 시간 적용 때도 4키가 덮어써진다(api_write.py:277~300). 그래서 파일이 있다고 「투자자가 저장한 적 있음」이 아니고, 파일 시각은 「마지막 저장 시각」이 아니다.
  - 저장 이력(v2_settings_history): 저장할 때 화면 값 25개(시험 종목·기간 포함)와 「source=업비트/바이낸스」 메모, 저장 시각(saved_at)을 남긴다(api_write.py:128~130·170~179). 다만 이 이력을 화면에 돌려주는 읽기 길은 아직 없다(v2/ 에서 찾음 — 저장 시각 한 줄 조회와 마지막 행 메모 조회만 있음, db.py:269). 새로 만들어야 한다.
- 권고: 저장 이력의 마지막 화면 값으로 연다. 투자자가 마지막으로 손댄 값 그대로(시험 종목·기간·출처 포함)이기 때문이다. 이력이 없으면 화면 기본값. 추적 손절 3칸은 이력에 들어가지 않으므로 늘 저장본에서 보탠다(api_write.py:121~130)(키 없음 = 「끔」, params_schema.py:89). 화면 위에 「불러온 설정: 마지막 저장 11/23 14:05」처럼 이력의 저장 시각을 보인다.
- 주의할 점:
  1. 저장만 하고 적용하지 않은 값이 열리면 운용 중 값으로 오해할 수 있다. 저장본·적용본이 다를 때 「운용 중 값과 다름」을 함께 보일지 계획 3판에서 정한다(db.py:242~265).
  2. 지금은 엔진 상태 응답이 온 뒤 종목·봉 단위를 덮어쓴다(bt_ui.js:409~413). 저장값을 채우는 순서를 정하지 않으면 봉 단위가 엔진 값으로 다시 덮인다. 옛 이력(칸이 모자란 행)과 깨진 행 처리도 함께 정한다.
  3. 투자비율은 백테스터 칸이 아니라 저장 창 칸이다. 저장 창은 이미 저장본에서 읽어 온다(save.js:124·290~293). 이번에 따로 할 일은 없다.
  4. 스윕·선물·차트 칸은 지금처럼 기본값으로 시작한다.
- 이 요청은 「체감 변경」이라 배포 전에 투자자 안내 대상이다(project-rules 투자자 연락 원칙 2번).

### 추가 2. 차트 탭에 백테스터 차트 모양 적용 — 가능 여부 질문
- 투자자 글: 「차트 부분 백테스트의 UI 적용가능여부 <= 이 차트에서 현재처럼 실제(live) 매수/매도 결과만 표시」.
- 읽은 뜻: 홈의 「차트」 탭을 백테스터 차트처럼 보이고 다루게 하되, 표식은 지금처럼 봇이 실제로 사고판 자리만 보인다(백테스트 결과는 넣지 않는다). 투자자가 「가능 여부」를 물었으므로 먼저 답이 필요하다.
- 두 차트의 차이(코드로 확인):

| 항목 | 지금 차트 탭 | 백테스터 차트 |
|---|---|---|
| 그리는 방법 | 차트 라이브러리(Lightweight Charts 4.2.0) | 화면에 직접 그림(canvas) |
| 봉 수 | 400봉부터 최대 2,000봉까지 모음(app.js:4~5·568~580) · 화면 글자만 「최근 200봉」(index.html:97) | 칸에서 정함(기본 1,500) |
| 확대·이동 | +/− 단추, 손가락 확대 | +/− 단추, 휠, 끌기 |
| 매수·매도 옆 시각·가격 글 | 없음 | 있음(YYMMDD_HHMM, 많으면 숨김) |
| 봉 정보 상자 | 없음 | 마우스·탭 위치 봉 정보 |
| 전체화면 | 없음 | 있음(아이폰도) |

- 답: 가능하다. 길은 두 가지다.
  - 길 가: 지금 차트 탭에 백테스터의 기능(시각·가격 글, 봉 정보 상자, 전체화면, 봉 수 늘리기)을 하나씩 더한다. 지금 차트의 실제 매수·매도 표식과 선 표시는 그대로 둔다.
  - 길 나: 백테스터의 그리기 코드를 차트 탭에서 다시 쓴다. 모양은 백테스터와 똑같아지지만, 지금 차트에 맞춰 둔 실제 매매 표식·선·시간대 처리를 새로 맞춰야 한다.
- 차트 탭은 이미 브라우저가 업비트에서 200봉씩 여러 번 받아 400~2,000봉을 모은다(app.js:568~580). 그래서 「길 가」의 봉 수 늘리기는 새 일이 아니라 이미 있는 값 조정에 가깝다. 화면 글자 「최근 200봉」은 실제와 다르므로 이번에 함께 바로잡을 대상이다. 서버 보관 시세 길(GET /v2/api/candles, api_read.py:1174)은 일 수로 받는 길이라 30초마다 다시 받는 차트에 맞는지는 확인하지 않았다(추정).
- 투자자에게 보낼 때(Fable 권고, 투자자 연락 원칙): 열린 질문으로 보내지 않는다. 「이렇게 이해했고 이렇게 진행한다, 다르면 알려 달라」로 한 번에 보내고, 보낸 글은 investor-notice-log.md 에 한 줄 적는다.
- 규모: 화면 고치기 5가지보다 크다. 별도 계획으로 나누는 것이 안전하다.

## 5. 운영자가 정할 것 (권고)

1. 추가 요청 2가지를 이번 고침에 넣을지 — 권고: 추가 1(백테스터 시작값)은 이번에 함께, 추가 2(차트)는 먼저 「가능, 길 가 권고」로 답하고 따로 계획.
2. 0.5% 줄의 상한 — 권고: 보유 1건당 40줄(1%일 때 20줄과 같은 움직임 폭을 덮음). 투자자에게 알린 「최대 20줄」이 바뀌므로 배포 전 안내에 적는다.
3. 백테스터를 열 때 쓸 값 — 권고: 저장 이력의 마지막 화면 값(시험 종목·기간·출처 포함, 추적 손절은 저장본에서 보탬) → 이력이 없으면 화면 기본값, 이력의 저장 시각 표시. 다른 길: 저장본 파일(종목은 저장 때 엔진 종목, 기간·출처 없음, 새 읽기 길이 필요 없음). 일의 크기: 이력안은 v2 서버에 읽기 길을 새로 만들어 서버 코드와 시험이 늘고, 저장본안은 화면 파일만 고친다. 둘 다 엔진은 건드리지 않는다. 이력안의 조건(계획 3판): 그 사용자 행만 읽기, 이력 DB 가 없으면 만들지 않기(db.py:276~278 과 같게), 바이낸스로 저장한 행이면 데이터 출처 칸도 되돌리기, 칸이 모자란 옛 행 처리.
4. 추가 2 「가능」 답을 보내는 방식 — 권고: 11/21 질문(연락 기록 18번)처럼 「이렇게 이해했고 이렇게 진행, 다르면 알려 달라」 한 번. 화면 고치기 배포 전 체감 변경 안내에 묶어 보낼 수도 있다.
