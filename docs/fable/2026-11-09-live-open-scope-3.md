## 제안 (사용자에게 올릴 안)
**기존 파라미터 설정을 쓰지 않고, 눌림목 전용 별도 칸 「투자 비율(%)」 1개를 신버전 저장 확인 창에 넣는다.**
- 이유: 기존 칸을 쓰면 EMA 비율과 값이 섞이고, 눌림목이 켜지면 그 페이지가 잠겨 바꿀 수 없음.
- 계산: 1회차(새 거래 시작) 때 업비트 가용 원화 × 투자 비율 = 이번 거래 배분 기준(거래 끝까지 고정, 기존 sizing_base_krw). 1회 금액 = 배분 기준 ÷ 분할 횟수. 코인 평가액은 넣지 않음(EMA 와 같이 가용 원화 기준).
- 효과: 앞 보고의 사고 2(모의 운용자산이 실제 금액)와 로그인 덮어쓰기 충돌이 사라짐. 사고 4(추정 손익이 금액에 들어감)는 실계좌에서 복리 더하기를 쓰지 않아 금액 영향이 사라짐(손익 표시는 별도로 고침). 소액 상한은 비율을 작게 시작하고 올리는 것으로 됨(⑤·⑥ 장치).
- 입력: 1~100 정수 아니어도 소수 허용 여부는 계획에서. 기본값 없음(실계좌는 비율이 없으면 전환 거절). 저장 창에 「지금 원화 · 비율 · 1회 금액」을 미리 보여 줌.
- 사용자 선택 나(금액 직접 지정)는 이 비율 칸으로 바꾸는 것을 권고하고 승인 때 함께 확인. 모의는 비율 없으면 지금과 같음(100%), 있으면 가상 잔고 × 비율.

### 빠짐없는 경우
비율 없음 → 실계좌 전환 거절 문구 / 범위 밖 → 저장 거절 / 1회 금액 5,000원 미만 → 저장 창 경고, 실행 때 회차 건너뜀 + 감사 기록 / 잔고 조회 실패·시간 초과 → 그 회차 건너뜀 + 감사 기록(주문 없음) / 가용 원화 0 → 건너뜀 / 보유 중 비율 변경 → 이번 거래 유지, 다음 거래부터 / 재시작 → 저장된 배분 기준 복원, 없으면 보유 중 추가 매수 멈춤 + 알림(남은 돈 기준으로 다시 계산하지 않음) / 앱 지정가로 묶인 원화 → 가용에서 제외.

### 알려야 할 차이
복리 「아니오」여도 실계좌 금액은 거래마다 잔고를 따라 변함(백테스터의 초기자본 고정 배분과 다름). 승인 요청서 「운용자산 ÷ 횟수」 → 「가용 원화 × 비율 ÷ 횟수」 변경이라 투자자 통보 대상(해제 때 체감 변경 통보에 포함).

- 권고 3: 정정 안내 제외(사용자 지시)와 해제 때 체감 변경 통보(프로젝트 규칙)는 다른 일임을 밝힘.
- 권고 4: 저장 창에 「새 거래 1회차 시작 때 가용 원화의 %」라고 안내.
- 사용자에게 물을 것: 기준 가용 원화 동의 / 나를 비율 칸으로 변경 / 모의에도 같은 칸.
