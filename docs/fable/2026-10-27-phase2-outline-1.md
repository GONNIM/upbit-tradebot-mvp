## Fable 답변서 1회째 (10/27, Agent model fable)

**판정:** 수정 후 진행
**이유:** 코드 근거(F1~F16·F19~F20)는 직접 읽어 맞음. D7·D10·D11(b-1) 권고가 요청서 7절·1절과 spec 확정 결정(v2 spec 4.6 D3, pullback spec 7.1)을 바꾸는데 D 표에 표시가 없어 「권고대로 전부」로 받으면 사용자가 모르고 승인할 수 있음.

질문별 답(요지): Q1 프로젝트 규칙과 부딪치는 것 없음, 요청서·spec 과는 D7(구버전 강제 매수 잠금)·D10(운용자산 고정)·D11(b-1)(앱 매수분 자동 매도 안 함) 셋이 다름(높음). Q2 이 셋은 「기존 결정 변경 요청」으로 표시해야 함 — PO 의 「없다고 봄」은 틀림(높음). Q3 D10 전체 기간 고정은 출금·손익 미반영 위험, (b-1)·(b-2) 가 봇 회차 0/1 로 보호가 갈림(보통). Q4 한 번에 받되 D2·D7·D10·D11 은 눈에 띄게(높음).

고쳐야 할 것: 1 막음 — D7·D10·D11(b-1) 에 「요청서·spec 과 다른 안 — 통보 문안 B 대상」, D2·T6 에 「실매매 DB 스키마 변경」 표시. 2 권고 — D10 에 「보유·예약 중에만」 선택지. 3 권고 — D11(b-1) 에 「(b-2) 와 같게」 선택지. 4 권고 — T2 전환 거절 조건을 저장본 기준으로. 5 권고 — T11 스레드 위치(엔진 프로세스 수준, 엔진 스레드 밖)·결과 파일 600. 6 권고 — 1-4 에 spec D8 인용, 「재확인」. 7 권고 — 문서 절 spec 4.5 160행.

사용자에게 물어야 할 것: D7·D10·D11(b-1) 범위, D5 부속(EMA 거래 시간 제한 미동작을 투자자에게 알릴지 — 연락 원칙상 대상 아니라 보나 운영자 판단).

(확인 못 함: verifier 4회는 세션 기록, F17·F18·F21 서버 실측.)

## PO 반영 (10/27)
- 막음 1: D7·D11(b) 권고를 요청서 범위 안으로 되돌림(구버전 강제 매수 열림, 앱 매수분도 미보유·보유 구분 없이 봇이 TP/SL·데드크로스 관리·추가 분할매수 멈춤). 요청서와 다른 안은 「다른 선택지」 칸에 「요청서·spec 과 다른 안, 통보 문안 B 대상」으로 표시. D10 은 「⚠ 기존 결정 변경 요청」 표시. D2 에 「⚠ 실매매 DB 스키마 변경 (T6 포함)」 표시.
- 권고 2~7 모두 반영(D10 권고를 「보유·예약 중에만」으로 좁힘, 선택지 3개).
- D5 부속은 사용자 결정 표에 넣음 → 실제로는 이 시점에 빠져 있었고, 다시 묻기 답 뒤 목차 D 표 D12 행으로 넣음.
