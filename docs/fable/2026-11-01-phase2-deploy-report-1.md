# 답변: 2차 배포 실행을 마쳤고(1시간 관찰·운영자 확인 포함), 완료 보고를 사용자에게 올리고 문서 커밋 승인을 받으려 함

**판정:** 수정 후 진행
**이유:** 배포 결과·3점 일치·커밋 범위·버전 갱신은 코드와 번들로 대조해 맞았습니다. 그러나 두 가지를 고친 뒤 올려야 합니다. 둘 다 사용자가 1101-05(고칠 범위)를 정하는 근거입니다.
- 보고 2-4 의 루프 겹침 원인 문장이 코드와 다릅니다. 정지가 기다리는 스레드와 실제로 살아남는 스레드가 다릅니다.
- 신버전 시작 요청에는 이미 겹침을 막는 장치가 있다는 사실이 빠져 있습니다.

1. **보고가 빠뜨린 것 두 가지**
   - **(가) 원인이 불완전합니다.**
     - `engine_manager.py:449` 가 10초 기다리는 것은 관리 스레드(`engine_runner_*`)입니다.
     - 매매 루프는 그 관리 스레드가 띄운 작업 스레드(`run_live_loop_*`, :625-633 → 정정 :628-634)입니다.
     - 관리 스레드는 작업 스레드를 `WORKER_JOIN_SEC=2.0`초(:168·:657)만 기다립니다. 그 뒤 `finally` 에서 잠금 해제(:675)와 등록부 삭제(:674)를 하고 끝납니다.
     - 그래서 16:45:33 에는 관리 스레드가 이미 끝났고, 작업 스레드만 16:46:32 까지 돌았습니다.
     - :449 뒤에 관리 스레드 생존을 확인해도 겹침을 못 막습니다. 고칠 대상은 작업 스레드 생존 확인입니다.
   - **(나) 신버전 시작 요청은 이미 막혀 있습니다.**
     - `control_requests.py:733-734` 는 `_stale_threads`(:716-720, `threading.enumerate()`)가 비어 있지 않으면 `old_engine_alive` 로 거절합니다.
     - `restart_engine`(:826-855)은 옛 스레드가 끝날 때까지 30초 기다리고, 넘으면 CRITICAL 로 멈춥니다.
     - 구멍은 구버전 시작 단추(`dashboard.py:663` → `start_engine`)와 `_start_engine_internal`(:400-406, 관리 스레드만 봄)입니다.
   - 사실 7 은 코드로 확인됐습니다.
2. **롤백 사유가 아닙니다.**
   - 배포 전 `1747fcc` 에도 같은 `join(timeout=10)`(:258)과 `user_lock.release()`(:480)가 있습니다.
   - 3절 1단계(`tradebot-v2` 정지)는 겹침을 막아 주는 신버전 시작 거절과 전환 대기까지 함께 닫습니다.
   - 구버전 정지·시작 단추는 그대로 남으므로 위험이 줄지 않습니다.
3. **「정지 뒤 2분」은 코드 상한 기준으로 부족합니다.**
   - 정지 신호는 `live_loop.py:1688` 루프 머리에서만 봅니다. 한 바퀴 안의 함수는 `stop_event` 를 받지 않습니다(`rest_reconcile.py:608-613`·:359-364·:843-848).
   - 대기 합계(HTTP 시간 제외):
     - 지터 5초
     - `fetch_confirmed_candle` 최대 17회 × 5초 = 85초(:656-667)
     - 400봉 조회 실패 시 1+2초
     - RETRY 5+8+10 = 23초
     - sleep 1초
   - 무거래 경로 약 97초, 실패 경로 약 129초입니다. VERIFY 불일치가 있으면 1건마다 30초가 더 붙습니다(:951-962).
   - pyupbit `requests.get` 은 timeout 이 없어 보입니다(추정).
   - 관측 81초는 무거래 경로입니다.
   - 안내는 「정지 뒤 3분 이상, 가능하면 시작은 신버전 단추로(`old_engine_alive` 거절)」로 바꿉니다.
4. **커밋 범위·버전 갱신은 규칙과 맞습니다.**
   - 요청서 2-8(:83) 「버전 갱신」, 선례 10/27·10/26 보고, HANDOFF:36 의도된 불일치와 같습니다.
   - zip 은 `.gitignore:95` 로 커밋에서 빠지고, 미추적 파일은 커밋 대상 밖입니다.
