## 남기는 작업 6개
| # | 작업 | 내용 |
|---|---|---|
| A | 모드 구분 + 실계좌 기동 허용 | 전환 때 모드 표식 파일 1개. 활성 PULLBACK + 표식 LIVE 일 때만 실계좌 기동. 표식 없음·이상이면 실계좌 PULLBACK 기동 거부 + CRITICAL. engine_manager·live_loop 거부를 이 판정으로 교체 |
| B | 실계좌 전환·복귀·적용·운용 설정 열기 | **실계좌 전환·복귀는 미보유·미체결 없음일 때만 즉시 처리, 보유 중이면 거절 문구(「매도 뒤 다시 눌러 주세요」). 실계좌 예약을 만들지 않는다.** 그래서 감시 스레드 5곳·예약 래퍼의 EMA 실계좌 적용이 필요 없음 |
| C | 투자 비율 칸 | 확정 결정대로. 저장 창 칸, 1회차 때 가용 원화 × 비율 ÷ (1+수수료) 고정, 실계좌 복리 더하지 않음, 비율 없음은 전환·적용·기동에서 거절, 실계좌 기동 변환은 virtual_krw 대신 MIN_CASH |
| D | 잔고 조회 실패 ≠ 청산 | coin_balance_checked 신설(EMA 의 _coin_balance 무변경), 빈 목록은 실패. 봉 시작 때 1회만 읽어 재사용, 실패 봉은 대조·청산 건너뛰고 메모리 수량으로 매도 판정. 강제 매수만 새로 읽음. 부팅 때 지갑 실패(재시도 뒤)는 저장 수량·평단으로 시작 + desync=1(추가 매수 멈춤, 매도 계속) + CRITICAL |
| E | 불확실 주문은 재주문 안 함 | 눌림목 시장가 매수(strict_amount)는 응답이 불확실(예외·시간 초과·5xx·비JSON·uuid 없음)하면 재시도 없이 멈춤. _pending_split(uuid 없음)을 세워 기존 3봉 대기 → 지갑 기준 맞춤(strategy_engine.py:1512-1530)으로 정리. _execute_pullback_buy 맨 앞 가드. 대기 중 지갑 0 청산 분기로 안 감. 재시도 호출은 EMA 경로 무변경 |
| F | 화면·시험 정리 | 신버전 실계좌 단추·문구, 구버전 실계좌 멈춤 화면 처리, 거부 고정 시험 교체, 바이트 고정 기준 이동 + EMA 호출 흔적 비교 |

# 답변 요지 (Fable, 원문의 판정·지적을 PO 가 옮겨 적음)

**판정:** 진행
**이유:** 빼는 항목 7가지를 코드로 따라가 보니 모두 추가 매수가 멈추는 쪽으로 떨어지고 매도 판정은 유지됨. 실제 돈 사고 빈틈 없음. 지적은 권고 4건.

- 권고 1 (E 에 반영): 3봉 뒤 지갑 기준 맞춤에서 has_position 거짓 + 지갑 > 0 이면 apply_entry(wallet, 업비트 평단)로 포지션을 세움. 평단 못 읽으면 desync. 시험 test_first_round_ambiguous_filled_sets_position_not_app_buy.
- 권고 2 (구현 전): 서버 로그에서 시장가 매수(bid/price) 응답 수를 세어 적음. 없으면 첫 투자자 주문이 첫 관측이라고 보고.
- 권고 3 (D 에 반영): 부팅 실패 때 저장 평단이 없으면 시작하지 않고 CRITICAL. 저장 수량 매도가 insufficient_funds_ask 로 거절되면 다음 봉에 지갑을 다시 읽어 맞춘 뒤 재시도.
- 권고 4 (사용자 보고에 반영): 요청서와 다른 점 표에 예약 없음·보유 중 재시작 안 함·입회 없음을 함께 적음.
- 구현 때 확인: 실계좌 처리 중 행 복구는 엔진 재시작을 부르지 않음, 표식 없음은 TEST.
