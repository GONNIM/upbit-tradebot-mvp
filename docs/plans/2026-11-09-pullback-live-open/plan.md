# 눌림목 분할매수(PULLBACK) 실계좌(LIVE) 열기 구현 계획서

> **에이전트 작업자용:** 필수 하위 기술은 superpowers:subagent-driven-development(권장) 또는 superpowers:executing-plans 입니다. 단계는 체크박스(`- [ ]`)로 적습니다. 이 계획서는 코드 본문이 아니라 「구현자가 혼자 정할 수 없는 결정」(파일·이름·시험·값)만 적습니다.

**목표:** 투자자가 신버전에서 직접 전환하면 눌림목 전략이 실계좌에서 백테스터와 같은 규칙으로 실제 주문을 내고, 체결·재시작·실패 때도 수량과 평단이 지갑과 맞게 한다.

**구조(요지):** (1) 활성 전략 파일 옆에 「모드 표식」 파일을 두어 모의와 실계좌를 가른다. (2) 눌림목 전용 「투자 비율(%)」 칸을 저장 파일 선택 키로 더하고, 1회차 때 가용 원화 × 비율을 배분 기준으로 고정한다. (3) 주문 식별자(identifier)와 체결 대기 영속으로 재시작·시간 초과 때 이중 매수와 체결 유실을 막는다. (4) 거부 지점을 모드 표식 판정으로 바꾸고, 모의 전제 코드를 모드별로 가른다.

**기술:** Python 3 · unittest(바깥 연결 없음) · SQLite(`pullback_state`) · 업비트 Open API(REST) · Streamlit(구버전) · 신버전 정적 JS(`v2/static`).

**근거 문서:** `docs/fable/2026-11-09-live-open-scope-1.md`·`-2.md`·`-3.md` · `docs/specs/v2-dashboard/plan-phase2.md:670-681,1102-1122,1197` · `docs/specs/v2-dashboard/investor-approval-20261021-v2.html`(6절·9절)

작성: 2026-11-09 · 코드 기준 HEAD `158c5fc`(이 문서의 코드 줄은 모두 이 커밋에서 읽음. 구현 착수 때 Task 0 으로 다시 확인)

### 4.1 방법

| 항목 | 값 |
|---|---|
| 실행 위치 | **서버에서 1회**(키가 등록된 IP 에서만 쓸 수 있고 맥에서 부르면 투자자에게 알림이 감 — `docs/operations/investor-notice-log.md` 7번 행). 맥에서는 가짜 응답 시험만 |

| 식별자 시험(지적 14) | 매수 요청에 `identifier`(실측용 `probe-<시각>-1`)를 붙이고, 체결 뒤 **그 식별자로 조회 1회**(응답이 uuid 조회와 같은지), 그리고 **쓰지 않은 식별자로 조회 1회**(없을 때 상태 코드·오류 이름이 무엇인지 — 계획이 404 로 가정한 값을 확정). 새 주문은 늘지 않는다 |

### 5.9 되돌리기

**순서: 2 → 3 → 1 → 4(필요 시) → 5.** (보유 확인 → 비율 키 제거 → 코드 되돌리기)

1. **코드 되돌리기(보유 중이 아님을 확인하고, 3번 키 제거를 끝낸 뒤)**: 신버전 「복귀」로 EMA 로 돌아가거나 엔진을 정지 → 활성 파일을 EMA 로 → 코드 `git revert` → 서버 `git pull` → `systemctl restart tradebot`·`tradebot-v2`. 남은 `pending_json` 칸·표식 파일은 옛 코드가 읽지 않아 무해(표식 파일은 지워도 됨).
2. **보유 중일 때(맨 먼저)**: 코드부터 되돌리지 않는다. 옛 코드는 활성 PULLBACK + 실계좌를 거부하고 **포지션을 관리하지 못한다**. 먼저 신버전 「강제 매도」(또는 업비트 앱 매도)로 정리 → 지갑 0 확인 → 3번 → 1번.
3. **비율 키 제거(verifier 11):** 옛 코드는 모르는 키를 거부(`engine/pullback_params.py:200-206`)하므로 저장·적용·`last_good` 사본 3개 파일에 `invest_ratio_pct_live`·`invest_ratio_pct_test` 가 들어 있으면 옛 `load_for_boot` 가 실패한다. 코드를 되돌리기 **전에** 5.4 백업에서 3개 파일을 복원하거나 두 키만 제거한다(제거 도구 `scripts/strip_ratio_keys.py <user>` — 값 출력 없음, 사본 `.pre-strip` 은 만들되 권한 600). 시험 `test_old_loader_accepts_file_after_strip`(기준 커밋의 `validate` 를 `git show` 로 읽어 실행).
4. **표식 파일 복구:** 표식이 비었거나 이상(`UNKNOWN`)해 보유 중 재시작이 거부되면(Q6 임시 선택 ①) → 업비트 앱에서 보유분 확인 → 운영자가 `<user>_active_strategy_mode.txt` 를 실제 모드(`LIVE`)로 원자적으로 다시 쓴 뒤 재시작(`scripts/write_active_mode.py <user> <LIVE|TEST>`, 쓰고 다시 읽어 확인). 복구 전 보유분은 봇이 관리하지 못하므로 **앱에서 직접 매도 가능**함을 알림 문구에 적는다.
5. 모든 경우 되돌린 뒤 `pullback_state` 를 지우지 않는다(분석용). DB 복원은 백업(5.4)에서 사용자 승인 뒤에만.
