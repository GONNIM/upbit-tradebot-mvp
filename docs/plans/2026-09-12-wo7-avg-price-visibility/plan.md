## 0. 범위 확정 (2026-09-12 승인 문구)

> WO-7은 현행 평균가 동작의 **화면 노출과 사용 여부 옵션**에 한정한다. avg 계산 로직 변경(슬리피지 반영, 부분 체결 정책 등)은 별도 워크오더로 분리한다.

즉 이 라운드는 **UI 표시 + 안내 문구** 수준의 경량 변경이다.

---

## 1. 목적 및 배경

### 1.1 목적

- 대시보드 포지션 카드에서 **진입가가 어디서 왔는지** 사용자에게 노출한다.
  - 봇 매수 (`bot_limit_fill` / `bot_market_fill`)
  - 외부 매수 (HTS → `position_state.avg_price` sync)
  - 강제 매수 (`force_buy_in`)
- 설정 페이지(매수 조건)에 **외부 매수 시 업비트 avg_buy_price 사용** 현행 동작 설명 문구를 노출한다.

### 1.2 배경

- V-A 조사에서 확인된 대로 HTS_BUY_ADD 감지 시 `avg_price sync` 로그가 정확히 남지만 UI에는 표시되지 않는다.
- 사용자가 매도 시점에 진입가의 유효성·출처를 즉시 판단할 수 없다.
- avg 계산 자체는 이미 정확히 작동 중이므로 로직 변경 없이 **표시성**만 개선.

## 2. 수정 파일·함수 목록

### 2.1 진입가 출처 표시 (대시보드)

| 파일 | 함수·라인 (예상) | 변경 |
|---|---|---|
| `pages/dashboard.py` | 포지션 카드 렌더 지점 (진입가·평단 표시 근처) | 진입가 옆에 출처 배지 (`봇 매수`/`외부 매수`/`강제 매수`) 표시 |
| `services/db.py` 또는 `services/position_helpers.py` (신설 검토) | 신규 헬퍼 | `get_position_entry_source(user_id, ticker) → str` — `audit_trades.reason` 최근 BUY row + `account_positions.meta.hts_buy` 참조 |

**출처 판정 규칙**:
- `audit_trades` 최근 BUY row의 `reason` 값 기준:
  - `EMA_GC`, `MACD_GC`, 기타 자동 크로스 → **"봇 매수"**
  - `HTS_BUY`, `HTS_BUY_ADD` → **"외부 매수 (HTS)"**
  - `force_buy` → **"강제 매수"**
- `account_positions.meta.hts_buy=True` 이고 최근 BUY 없음 → **"외부 매수 (감지)"** (예외 처리)

### 2.2 설정 페이지 안내 문구

| 파일 | 위치 (예상) | 변경 |
|---|---|---|
| `pages/set_buy_sell_conditions.py` | 매수 조건 섹션 하단 | `st.info` 또는 `st.caption` 안내 신설 |

**문안 예시**:
```
ℹ️ 외부(HTS) 매수 안내: 봇이 HTS 매수를 감지하면 업비트 계정의 실제 avg_buy_price 값을
사용합니다. 이 값은 봇 감지 즉시 자동 반영되며 매도 필터(SL/TP/Trailing) 계산에 그대로
쓰입니다. 계산 방식(슬리피지·부분 체결 등)은 이번 라운드에서 변경되지 않습니다.
```

## 3. 토글 신설 검토 (찬반) — 옵션 A vs 옵션 B

사용자 지시: "옵션 토글은 '끄면 대체 동작이 무엇인가'가 정의되지 않으므로, 토글 신설의 실익과 위험(끔 상태의 의미 부재)을 찬반으로 정리하고 초안 권고를 제시하라."

### 3.1 옵션 A: 토글 신설 (`use_upbit_avg_for_external_buy`)

**찬**:
- 사용자에게 명시적 통제감. 향후 avg 계산 옵션 확장 시 확장점.
- 설정 페이지에 표시 필요성이 있으므로 UI 자리 마련 겸용.

**반**:
- **끔 상태의 대체 동작 미정의** — HTS 매수 감지 후 avg를 무엇으로 세팅할지 결정 안 됨.
  - 후보 1: `None` 유지 → 매도 필터 스킵 (SL/TP/TS 무력화, `avg_price_missing` CRITICAL 발화 · [[project_upbit_hts_sl_paralysis_fix]] 사례 재발)
  - 후보 2: 마지막 체결가 → 계산 부정확
  - 후보 3: 봇 매수 대기 → 외부 매수를 자동매매 대상으로 두지 않겠다는 뜻인데 이 경우 봇의 매도 개입도 안 됨 (사용자 의도와 불일치)
- **끔 상태 사용 시 실 손실 위험**: 어느 후보든 매도 무력화 또는 부정확한 결정 유발.
- 토글이 실제로는 절대 끄면 안 되는 옵션이 됨 (UI에는 있지만 켜기 강제).

### 3.2 옵션 B: 토글 미신설, 안내 문구만 (권고)

**찬**:
- 현행 동작(업비트 avg 사용) 자체가 이미 안전한 정답. 대체 동작이 없다면 옵션이 아니다.
- 안내 문구로 사용자에게 동작 방식은 설명하되 통제권은 주지 않음.
- 향후 avg 계산 방식 변경 시 (별도 워크오더) 그때 옵션 재검토.
- **끔 상태 실 손실 위험 원천 봉쇄**.

**반**:
- 사용자 통제감 축소. 명시적 옵션 부재.
- 대체 완결.

### 3.3 초안 권고

**옵션 B (토글 미신설, 안내 문구만) 권고.** 근거:
1. 대체 동작 미정의 상태로 토글 신설은 실 손실 위험을 신규 도입.
2. 현행 동작이 이미 정답. 옵션의 두 상태가 필요하다는 조건이 성립하지 않음.
3. 사용자에게 동작 방식은 안내 문구로 충분히 노출 가능.
4. avg 계산 로직 변경은 별도 워크오더 스코프. WO-7은 표시성만.

**사용자 최종 판정 대상**. 옵션 A 선택 시 §3.1의 반 근거를 어떻게 봉쇄할지 함께 결정 필요.

## 4. avg 계산 로직 무변경 원칙 (재명시)

**본 라운드는 다음을 건드리지 않는다**:
- `position_state.avg_price` 계산 방식
- HTS-DETECT-CALLBACK의 `position_state.avg_price` 동기화 로직
- `bot_limit_fill` · `bot_market_fill` 콜백의 `apply_entry` 진입가 세팅
- `audit_trades.entry_price` 계산 · 저장 방식
- Upbit REST `avg_buy_price` 조회·사용

**이 원칙은 계획서 §1.1 표에도 명시**. 파일 diff에 avg 계산 관련 코드 변경이 있으면 즉시 배포 차단.
