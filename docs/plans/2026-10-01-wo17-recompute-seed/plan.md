## 0. 한 줄 요약

한 번도 동작하지 않으면서 "완료" 로그만 남기는 부분 재계산 경로를 정리하고(P), 지표 시드를 200봉 SMA 대신 긴 이력 증분 계산으로 바꿔 기동 직후 EMA 오차를 줄이며(S), 사실과 다른 주석 2곳을 고친다(C). 매수·매도 판정 조건은 바꾸지 않는다. 다만 (S)는 지표 값 자체를 바꾸므로 크로스 시점이 달라질 수 있다(§2 (S) 위험).

## 1. 원칙

1. 커밋 분리, 순서 (C) → (P) → (S). 위험이 낮은 것부터. 각 단독 revert.
2. (C)는 **주석만**(Issue #8 `fetch_confirmed_candle` 코드 무변경 조건). 로그 문자열은 손대지 않는다(승인 항목 G1 제외 시).
3. (S)는 배포 전 과거 데이터로 "기존 시드 vs 새 시드" 의 크로스 시점 차이를 측정해 보고한다.

### (P) 부분 재계산 경로 정리 — 커밋 2

**현재 (실측)**
- `core/strategy_engine.py:776~791` 조정 변경이 있으면 `recompute_from_changed_ts(full_series, changed_ts)` → `core/indicator_state.py:183~227` 꼬리(가장 이른 변경 봉 이후)로 `seed_from_closes` 시도.
- 꼬리는 늘 1~3봉이라 `Not enough data for seed: N < 200` 으로 실패, 상태 무변화. 그런데 `[INDICATORS] 부분 재계산 완료` 가 찍힌다. journal 보존분(08-31~) 실패 8,199건, 성공 0건.
- WO-16 뒤에도 매 주기 확정 대상 봉이 새로 들어와(형성 중 봉을 미리 받지 않으므로 `inserted`) `changed=1` → 같은 실패가 반복된다(관측으로 확인 예정, §4).
- **잠재 위험**: 꼬리가 200봉 이상이면(200봉 이전의 오래된 봉 값이 REST 에서 바뀌는 경우) SMA 로 다시 시드한 뒤 현재 봉을 `update_incremental` 로 한 번 더 넣어 **현재 봉 이중 반영 + EMA 연속성 단절 + `prev_ema` 초기화(크로스 판정 1회 누락)** 가 생긴다. WO-16 으로 조정 수신이 293→400 으로 늘어 오래된 봉이 비교 대상에 들어오므로 이 조건의 가능성이 지금보다 커진다(사전 측정상 오래된 봉 불일치는 0 이었음).

**선택지**

| 안 | 내용 | 장점 | 단점·위험 |
|---|---|---|---|
| **P1 (권고)** | `recompute_from_changed_ts` 호출을 없애고 증분 갱신만(`update_incremental`) 한다. 조정 변경은 `[ENGINE] Reconcile 변경 감지 … (지표는 증분만, 재시드 없음)` 로그로 남긴다 | 보존 기간 내 실제 동작 0회라 지표 동작은 사실상 그대로. 이중 반영 잠재 위험 원천 제거. "완료" 오기 소멸 | 과거 봉 값이 실제로 바뀐 경우 그 차이가 지표에 반영되지 않는다(지금도 반영 안 됨) |
| P2 | 경로는 두되 꼬리 < 시드 필요 수면 조용히 건너뛰고(로그 정정), 꼬리 ≥ 필요 수면 재시드하지 않고 경고만 | 관측성 유지 | 코드 경로가 남아 혼동 지속 |
| P3 | 바뀐 봉 이전 상태부터 정확히 다시 증분 계산(봉별 지표 이력 저장 필요) | 과거 봉 변경을 정확히 반영 | 지표 이력 저장·복원 설계가 큼, Issue #11(BACKFILL 백업·복원)과 상호작용, 이번 WO 범위 초과 |

- 테스트: (1) changed_count>0 에서 지표가 `update_incremental` 1회와 같은 값 (2) 꼬리 ≥ 200 입력에서도 재시드·이중 반영 없음 (3) "부분 재계산 완료" 문구 소멸 (4) 대조: 옛 경로로 꼬리 250 입력 시 이중 반영 재현.

### (S) SMA 시드 → 긴 이력 증분 계산 — 커밋 3

**현재**: `seed_from_closes` 가 각 EMA 를 마지막 N개 SMA 로 시작. 워밍업 200봉뿐이라 EMA200 은 200봉 SMA 그 자체. WO-15 실측(2026-10-01 11:40 시드): 1,200봉 장기 기준 대비 EMA60 −2.42원, EMA200 +2.42원, (60−200) 차이 엔진 −12.76 대 기준 −7.92(**4.8원**).

**변경**: 워밍업 조회를 `min_hist + 여유` 로 늘리고, 가장 오래된 N봉 SMA 로 시작해 이후 봉을 **증분으로 순서대로** 반영해 현재 봉 직전까지 계산한다(실시간 증분과 같은 식).

**필요 이력 길이** (잔차 = 초기 SMA 시작 오차 × (1−a)^k, a = 2/(N+1))

| EMA | a | 잔차 1% 까지 k | 잔차 0.1% 까지 k | 필요 봉 수(시작 N + k) |
|---|---|---|---|---|
| EMA60 | 0.03279 | 139 | 208 | 199 / 268 |
| EMA200·기준 EMA | 0.00995 | 461 | 691 | 661 / 891 |
| MACD(12/26/9) | — | 짧음 | 짧음 | EMA200 기준에 포함 |

- 제안: **800봉**(EMA200 잔차 약 0.25%, EMA60 사실상 0). 대안 600봉(EMA200 잔차 약 1.8%), 1,000봉(약 0.03%).

| 601 | 4 | 0.6~1초 | |

- 기동 1회만 늘어난다. 조정(400)·VERIFY(220)는 그대로. Upbit 시세 API 요청 제한(초당 10회 수준) 안.
- 버퍼(`CandleBuffer`)는 지금처럼 최근 `min_hist` 봉만 채우고, 지표 계산에만 긴 이력을 쓴다.
- `local_series`(조정 기준 시계열)를 긴 이력으로 시작할지 최근 200봉으로 자를지는 승인 항목 G3(WO-14 (b) 로컬 시작 기준과 연동).

**위험**

| 위험 | 대응 |
|---|---|
