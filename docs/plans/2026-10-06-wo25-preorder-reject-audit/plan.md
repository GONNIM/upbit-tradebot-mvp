## 2. 변경 (B, 최소 범위)

- **유형 재사용**: audit_trades `type='BUY_REJECTED'` (WO-9). 감사 로그 페이지의 ⛔ 매수 거절, '거절 사유' 열, 유형 필터 "거절" 을 그대로 쓴다. 화면 코드는 바꾸지 않는다.
- **구분**: meta `stage='pre_order'`, `error_name` 에 분기 코드를 넣는다. 거래소 거절(WO-9)은 meta 에 업비트 오류 코드와 http_status 가 있다.
- **사유 문구**: note 칸에 사람이 읽는 문구를 넣는다.
  - 예: `매수 가능 KRW 부족 (가용 1원, 주문 비율 적용 주문액 0원 < 최소 5,000원) — 현재가 매수 주문 전 차단`
  - 지시 예시의 "필요 811,830원" 꼴은 쓰지 않았다. 이 분기의 기준은 최소 주문액 5,000원이고, 평소 주문액은 그 순간의 가용 KRW × 주문 비율이라 따로 정해진 "필요액" 이 없다. 대신 가용·주문 비율 적용 주문액·최소액을 함께 적는다.
- **트레이더** (`core/trader.py`)
  - `_audit_reject(note=…)`: note 를 주면 그 문구를 쓴다. 기본은 그대로 `reject_note(err_summary)`.
  - `_audit_preorder_reject` 를 새로 둔다.
  - buy_limit 5분기: 호가 계산 실패, 호가 이탈, KRW 0, KRW 부족, 수량 0
  - buy_market 2분기: KRW 0, 최소 주문액 미만
- **엔진** (`core/strategy_engine.py`)
  - `_audit_buy_blocked` 를 새로 둔다. meta 는 `_execute_buy` 와 같은 모양이다.
  - execute: 매매 일시중지(BUY 일 때만), 앞선 주문 진행 중, 지표 오염
  - `_execute_buy`: 이미 보유
  - `_audit_wo2_resolution(validation_passed=0)`: 지연 매수가 주문 없이 끝난 3사유 (SUPERSEDED, MAX_WAIT_EXCEEDED, SIGNAL_INVERTED)
- **바꾸지 않는 것**: 판정식, 필터, 발주, 알림, 반환값, 화면 코드, 과거 DB 행
- **대상이 아닌 것**: dry-run(검증 모드), TEST 모드 폴백, 급등 필터(평가 단계), BACKFILL 주문 생략(설계)
- **부수 효과** (같은 트레이더 함수를 쓰는 경로)
  - 강제 매수 (`services/trading_control.py`, reason=force_buy)
  - WO-24 미체결 시장가 전환 (`buy_market(krw_amount=…)`)
  - 두 경로도 주문 전 차단 시 BUY_REJECTED 1행을 남긴다.
